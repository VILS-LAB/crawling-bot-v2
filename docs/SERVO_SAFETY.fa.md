# ایمنی حرکت سروو

دو سرووی پا تنها بخشی از ربات هستند که یک سیاست (policy) دانشجو می‌تواند
واقعاً خرابشان کند. سیاستی که یک‌باره از ۲۰ درجه به ۱۶۰ درجه بپرد، جریان
لحظه‌ای زیادی می‌کشد، چرخ‌دنده را می‌تراشد یا پا را به زمین می‌کوبد.

`lib/ServoControl` این کار را عمداً سخت می‌کند. **هر** حرکت عمومی از یک پروفایل
حرکت ذوزنقه‌ای عبور می‌کند و درایور جای هر پا را به یاد دارد، بنابراین هدف جدید
همیشه از موقعیت واقعی شروع می‌شود، نه با یک پرش.

## چه چیزهایی تضمین می‌شود

| تضمین | چطور |
|---|---|
| بدون پرش لحظه‌ای | هر حرکت رمپ‌دار است: شتاب → سرعت ثابت → کاهش سرعت |
| بدون رد شدن از هدف | نقطه ترمز از فاصله باقی‌مانده محاسبه می‌شود |
| بدون پرش هنگام تغییر هدف | هدف جدید در میانه حرکت فقط باعث ترمز و تغییر مسیر می‌شود |
| بدون کوبیدن به زمین | محدوده‌های نرم هم روی هدف و هم روی هر گام پروفایل اعمال می‌شوند |
| بدون حرکت ناگهانی بعد از توقف حلقه | `update()` مقدار `dt` را به `SERVO_UPDATE_MAX_DT_MS` محدود می‌کند |
| موقعیت همیشه معلوم است | `getCurrentDownAngle()` / `getCurrentUpAngle()` |

تنها نوشتن لحظه‌ای اجتناب‌ناپذیر، پارک اولیه در `begin()` است: تا سروو حرکت
نکند، فریم‌ور نمی‌داند شاخک کجاست. **قبل از روشن کردن ربات، پاها را در حالت
پارک قرار دهید.**

## دو روش حرکت

### غیرمسدودکننده (پیشنهادی)

```cpp
void loop() {
    servos.update();        // must run every loop

    servos.moveDownTo(120); // sets a target, returns immediately
    servos.moveUpTo(60);
}
```

`update()` ارزان است و هرگز مسدود نمی‌کند. هر دو پروفایل را به اندازه زمان
سپری‌شده جلو می‌برد و فقط وقتی زاویه گردشده تغییر کند، PWM را می‌نویسد.

### مسدودکننده

```cpp
servos.moveDownSmooth(120);   // returns when the leg arrives
servos.moveBothSmooth(120, 60);
```

این‌ها هم رمپ‌دار هستند؛ فقط داخلاً روی `update()` می‌چرخند. در `setup()` یا
یک اسکچ ساده مناسب‌اند، ولی تا پایان حرکت، نمایشگر، OTA و تله‌متری را متوقف
می‌کنند.

## تست سرووها از سریال مانیتور

در `src/main.cpp` یک کنسول تست کوچک هست. سریال مانیتور را روی ۱۱۵۲۰۰ با
پایان‌خط newline باز کنید و تایپ کنید:

| دستور | کار |
|---|---|
| `d <angle>` | پای پایین را به `<angle>` ببر (۰ تا ۱۸۰) |
| `u <angle>` | پای بالا را به `<angle>` ببر |
| `b <down> <up>` | هر دو پا |
| `s` | هر دو پا را همان‌جا متوقف کن |
| `p` | به حالت پارک (اولیه) برو |
| `t` | به حالت تست (۹۰/۹۰) برو |
| `?` | زاویه و هدف فعلی را چاپ کن |

هر دستور از پروفایل رمپ‌دار عبور می‌کند، پس حتی یک اشتباه تایپی مثل `d 180`
هم نمی‌تواند پا را به زمین بکوبد. منوی کالیبراسیون IMU (`q`) هم دست‌نخورده
کار می‌کند؛ کنسول سروو مزاحمش نمی‌شود.

## تنظیم

همه در [include/config.h](../include/config.h):

| ماکرو | پیش‌فرض | معنی |
|---|---|---|
| `SERVO_MAX_SPEED_DPS` | `180.0f` | سرعت ثابت، درجه بر ثانیه |
| `SERVO_ACCEL_DPS2` | `600.0f` | شتاب، درجه بر ثانیه مربع |
| `SERVO_DOWN_MIN_ANGLE` / `SERVO_DOWN_MAX_ANGLE` | `0` / `180` | محدوده نرم پای پایین |
| `SERVO_UP_MIN_ANGLE` / `SERVO_UP_MAX_ANGLE` | `0` / `180` | محدوده نرم پای بالا |
| `SERVO_UPDATE_MAX_DT_MS` | `50` | بزرگ‌ترین گام زمانی یک `update()` |

با مقادیر پیش‌فرض، یک حرکت کامل ۱۸۰ درجه‌ای حدود **۱.۳ ثانیه** طول می‌کشد.
اگر پاها هنوز به زمین می‌خورند سرعت را کم کنید؛ اگر ربات کند است زیاد کنید.

محدوده‌های نرم را به بازه واقعی و ایمن ربات مونتاژشده محدود کنید — این مؤثرترین
محافظت است، چون باعث می‌شود یک عمل خارج از محدوده از سمت سیاست، بی‌اثر شود
نه اینکه به برخورد منجر شود.

تنظیم در زمان اجرا:

```cpp
servos.setSpeed(90.0f);    // degrees per second
servos.setAccel(300.0f);   // degrees per second squared
servos.setDownLimits(20, 160);
servos.setUpLimits(20, 160);
servos.stop();             // freeze both legs where they are
```

## خلاصه API

| متد | مسدودکننده؟ | توضیح |
|---|---|---|
| `moveDownTo(angle)` / `moveUpTo(angle)` | خیر | هدف را تنظیم می‌کند، به محدوده نرم محدود می‌شود |
| `moveBothTo(down, up)` | خیر | هر دو هدف با هم |
| `update()` | خیر | در هر `loop()` صدا بزنید |
| `isMoving()` | خیر | تا وقتی یکی از پاها در حرکت است true |
| `stop()` | خیر | هدف := موقعیت فعلی |
| `moveDownSmooth(angle)` / `moveUpSmooth(angle)` | بله | رمپ‌دار، با رسیدن برمی‌گردد |
| `moveBothSmooth(down, up)` | بله | رمپ‌دار، با رسیدن هر دو برمی‌گردد |
| `waitUntilIdle(timeoutMs = 0)` | بله | مقدار `0` یعنی تخمین از پروفایل |
| `moveDown(angle)` / `moveUp(angle)` | بله | نام‌های قدیمی، حالا رمپ‌دار |
| `setInitialPosition()` / `setTestPosition()` | بله | حالت‌های آماده رمپ‌دار |
| `setSpeed()` / `setAccel()` | خیر | تنظیم زمان اجرا |
| `setDownLimits()` / `setUpLimits()` | خیر | محدوده نرم زمان اجرا |
| `getCurrentDownAngle()` / `getCurrentUpAngle()` | خیر | موقعیت فرمان‌داده‌شده |
| `getDownTarget()` / `getUpTarget()` | خیر | هدف فعلی |

### آرگومان قدیمی `stepDelay`

متد قدیمی `moveDownSmooth(angle, stepDelay)` هر `stepDelay` میلی‌ثانیه، ۲ درجه
حرکت می‌کرد. آن آرگومان هنوز پذیرفته می‌شود و به سرعت ثابت `2000 / stepDelay`
درجه بر ثانیه تبدیل می‌شود، بنابراین اسکچ‌های قبلی همان حس را دارند — ولی حالا
رمپ و محدوده نرم را هم می‌گیرند. مقدار `0` (پیش‌فرض) یعنی از
`SERVO_MAX_SPEED_DPS` استفاده شود.

## پروفایل چطور کار می‌کند

`lib/ServoControl/ServoMotion.h` یک تولیدکننده ذوزنقه بدون وابستگی است، و همین
اجازه می‌دهد روی هاست تست شود:

```
speed
  ^
  |      ______________
  |     /              \
  |    /                \
  |   /                  \
  +--+--------------------+----> time
     accel   cruise   decel
```

هر `update()`:

1. مقدار `dt` را به `SERVO_UPDATE_MAX_DT_MS` محدود می‌کند،
2. بیشترین سرعتی را حساب می‌کند که هنوز توقف کامل در فاصله باقی‌مانده را ممکن
   می‌کند (حد ترمز گسسته)،
3. سرعت را به سمت آن مقدار می‌برد، هرگز تندتر از `accel`،
4. زاویه را انتگرال می‌گیرد و هنگام رسیدن دقیقاً روی هدف می‌نشیند،
5. به محدوده نرم محدود می‌کند.

چون حد ترمز در هر گام از فاصله *فعلی* دوباره حساب می‌شود، تغییر هدف در میانه
حرکت ایمن است: پا فقط ترمز می‌کند و به سمت هدف جدید می‌رود.

## تست‌ها

پروفایل با تست‌های هاست پوشش داده شده که به سخت‌افزار نیاز ندارند:

```bash
test/host/run.sh
```

این تست‌ها بررسی می‌کنند که محور دقیقاً روی هدف بنشیند، از محدوده سرعت و شتاب
عبور نکند، از هدف رد نشود، هنگام تغییر هدف پیوسته بماند، محدوده نرم را رعایت
کند و با مقادیر `dt`/تنظیمات خراب هم کار کند.

## چه چیزهایی محافظت نمی‌شود

- **سیم‌کشی اشتباه یا سرووی مرده.** از چک سلامت بوت
  ([SERVO_HEALTH.md](SERVO_HEALTH.md)) استفاده کنید.
- **پایی که مکانیکی گیر کرده.** پروفایل با سرعت تنظیم‌شده فشار می‌آورد؛ حسگر
  جریان برای تشخیص گیر کردن وجود ندارد.
- **موقعیت هنگام روشن شدن.** نوشتن پارک در `begin()` ناچاراً لحظه‌ای است.
- **دانشجویی که درایور را دور بزند** و مستقیم `servo.write()` صدا بزند.
